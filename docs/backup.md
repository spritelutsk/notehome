# Резервное копирование

Ночная копия базы и загруженных документов на домашний компьютер `192.168.1.100`
(Windows, диск `I:`). Всё, что делает Pi, — в [`scripts/backup.sh`](../scripts/backup.sh);
расписание держит systemd.

## Как это работает

Таймер `spritenote-backup.timer` будит службу в 9:00. Компьютер-приёмник включён не всегда,
поэтому скрипт не падает, а ждёт:

1. раз в 10 минут проверяет, отвечает ли на `192.168.1.100` порт 445;
2. дождавшись, выжидает ещё 5 минут. Пауза не косметическая: сразу после включения Windows
   ещё поднимает службы и монтирует диски, и запись в этот момент может уйти в никуда;
3. если за время паузы машина успела выключиться — возвращается к ожиданию;
4. не дождавшись до 22:00, тихо выходит: таймер разбудит службу завтра.

Проверяется именно порт, а не `ping`: Windows часто глушит ICMP, продолжая отдавать файлы.

## Что попадает в копию

`mysqldump --single-transaction` (снимок без блокировки таблиц, приложение продолжает работать)
плюс каталог `data/uploads` — в один `notehome-ГГГГ-ММ-ДД-ЧЧММ.zip`.

ZIP, а не `tar.gz`: копия лежит на Windows, там архив открывается двойным кликом без стороннего
архиватора. Собирается двумя вызовами `zip`, потому что дамп и `uploads` лежат в разных местах,
а второй вызов дописывает в уже существующий архив.

Пароль базы уходит в `mysqldump` временным файлом, а не аргументом: аргументы видны в `ps`
любому пользователю системы.

## Копия только при изменениях

Перед отправкой скрипт считает отпечаток: SHA-256 дампа плюс список файлов в `uploads`
с размерами и временем правки. Отпечаток прошлой удачной отправки лежит в
`/var/lib/spritenote-backup/last.sig`. Совпал — ничего не отправляется.

Две тонкости, обе намеренные:

- дамп снимается с `--skip-dump-date`. Иначе в шапке стоит время выгрузки, два одинаковых
  слепка отличались бы этой строкой, и «изменения» находились бы каждый день;
- отпечаток записывается **только после удачной отправки**. Иначе неудачная попытка «съела» бы
  изменение, и назавтра скрипт решил бы, что копировать нечего.

Документы учитываются наравне с базой: на диске они лежат файлами, в базе от них только имена,
и подменённый файл иначе остался бы незамеченным.

## Хранение

На той стороне держатся две последние копии, лишние удаляются после успешной отправки новой.
Имена начинаются с даты в порядке год-месяц-день, поэтому сортировка по алфавиту и есть
сортировка по времени.

## Файлы

| Путь | Что это |
|---|---|
| `scripts/backup.sh` | сам скрипт, в репозитории, секретов не содержит |
| `/etc/spritenote-backup.conf` | адрес, имя ресурса, папка, интервалы, сколько копий хранить |
| `/etc/spritenote-backup.auth` | логин и пароль Windows, права 600, владелец `sergey` |
| `/etc/systemd/system/spritenote-backup.{service,timer}` | расписание |
| `/var/lib/spritenote-backup/last.sig` | отпечаток последней отправленной копии |

Учётные данные лежат **вне каталога проекта** намеренно: `GET /api/admin/project-zip` отдаёт
проект целиком, и файл с паролем от домашнего компьютера туда попадать не должен. Полностью это
не защита — у администратора есть веб-терминал, то есть shell от имени `sergey`, — но одной
случайной утечкой меньше.

## Как настроен доступ

Диск `I:` виден по сети только как административный ресурс `I$`, а он открывается лишь учётной
записи с правами администратора на той машине (и, как правило, требует ещё и
`LocalAccountTokenFilterPolicy`). Учётная запись `serdum`, под которой ходит Pi, туда не
допущена — проверено, `NT_STATUS_ACCESS_DENIED`.

Поэтому папка `I:\архив notehome` отдана отдельным общим ресурсом `notehome` с правом записи
для `serdum`. Так и правильнее: пароль от Windows лежит на Pi открытым текстом, и давать по нему
доступ ко всему диску незачем. Ресурс указывает прямо на нужную папку, поэтому `SMB_SUBDIR`
пуст:

```sh
SMB_SHARE=notehome
SMB_SUBDIR=''
```

Если однажды вместо этого будет расшарен весь диск `I:` под именем `I`, настройки станут
такими — скрипт понимает оба варианта:

```sh
SMB_SHARE=I
SMB_SUBDIR='архив notehome'
```

## Проверка и обслуживание

```bash
systemctl start spritenote-backup.service     # прогнать прямо сейчас
journalctl -u spritenote-backup -n 50         # что было в последний раз
systemctl list-timers spritenote-backup.timer # когда следующий запуск
```

Прогон без ожидания сети и без записи отпечатка в общее место — с временным конфигом:

```bash
STATE_DIRECTORY=/tmp/bk SPRITENOTE_BACKUP_CONF=/путь/к/test.conf ./scripts/backup.sh
```

Чтобы заставить скрипт отправить копию при неизменившихся данных, удалите
`/var/lib/spritenote-backup/last.sig`.

## Восстановление

```bash
unzip notehome-ГГГГ-ММ-ДД-ЧЧММ.zip                # получаем dump.sql и uploads/
sudo mariadb -u root spritenote < dump.sql
rsync -a uploads/ /home/sergey/Documents/note/data/uploads/
sudo systemctl restart spritenote
```

Дамп содержит `DROP TABLE ... CREATE TABLE`, то есть заливается поверх существующей базы.
Если нужно сначала посмотреть, что внутри, — разворачивайте во временную базу
(`spritenote_test`), рецепт в конце [AGENTS.md](../AGENTS.md).
