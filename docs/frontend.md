# Фронтенд

Три файла: `public/index.html` (вся разметка, включая модалки), `public/css/style.css`,
`public/js/app.js` (всё поведение). Никакой сборки — что лежит на диске, то и уходит в браузер.
`app.js` целиком обёрнут в IIFE, глобальных имён не создаёт.

## Состояние

Один объект `state` в начале `app.js`:

```js
state = {
  user, nodes, selectedFolderId, expanded, view, authMode,
  itemModal, moveModal, filesPath, terminal, settings, searchQuery,
  filter, textReader, selection, selectionAnchor,
}
```

`state.filter` — отбор в обход дерева: `{ favorites }`. Пока он не пуст, правая часть
показывает выборку по всему дереву, а не содержимое папки, — как и поиск. Клик по папке из
отбора выходит, иначе дерево перестало бы отзываться на клики.

Битые ссылки в отбор **не входят намеренно**: они помечаются значком на карточке там, где
лежат, и никуда не собираются. Отдельная строка-список в панели читалась как «папка, куда
их перенесли», а переноса нет и не должно быть.

`state.nodes` — плоский список всего дерева, полученный одним `GET /api/nodes`. Иерархия
считается на лету (`childrenOf`, `foldersOf`, `pathTo`), поиск — тоже на клиенте, по всем полям
сразу. Перерисовка тупая и полная: `renderTree()` / `renderContent()` собирают DOM заново.
Для такого объёма данных это дешевле, чем любая инкрементальная схема.

## Вкладки

`switchView(view)` показывает один из шести блоков: `explorer`, `help`, `trash`, `admin`,
`notepad`, `terminal`. Первые три доступны всем, остальные три — только администраторам.

`trash` — экран «Недавно удалённое». Он единственный, кроме админских, ходит за данными сам
(`loadTrash()` при открытии вкладки, при смене языка и после каждого действия), а не читает
`state.nodes`: корзина в общий список дерева не попадает. Путь «откуда» при этом всё-таки
берётся из `state.nodes` — родитель удалённого узла по определению жив, иначе строка не
показывалась бы вовсе.

Всё, что видно только администратору (три вкладки, кнопки экспорта/импорта дерева, админские
части «Инструкции»), переключается одной функцией `applyAdminVisibility()`. Она вызывается
дважды: при входе в приложение и после смены роли пользователя в панели управления — роль можно
снять с самого себя, и интерфейс обязан перестроиться сразу.

## Клавиатура

Клавиши одиночные, без модификаторов — так быстрее, но каждая обязана молчать там, где человек
набирает текст. За это отвечает одна проверка `typingNow()`: поля ввода, `textarea`, `select`,
редактируемые области и терминал (там любая буква должна уйти в shell). Второй охранник —
`anyModalOpen()`: при открытом окне буквенные клавиши не работают.

`Esc` — единственное исключение из обеих проверок: он обязан работать всегда, иначе из окна
не выйти. `closeTopmostModal()` закрывает окна по приоритету сверху вниз, и только если ни
одного не открыто, `Esc` снимает выделение, а затем очищает поиск.

Стрелки работают там, где сейчас фокус: в дереве — по видимым строкам (свёрнутые ветки в список
не попадают, поэтому стрелка идёт туда же, куда ведёт глаз), на карточках — по сетке. Если
фокуса нет вообще, стрелка вниз заходит в дерево — иначе с клавиатуры не начать. Фундамент
для этого заложил `makeActivatable()`: он давно ставит `tabIndex` и роль на строки и карточки.

Ловушка, на которую легко наступить: `renderTree()` пересобирает DOM целиком, поэтому после
разворачивания папки прежний элемент фокуса уже выброшен. Фокус возвращается поиском строки
по `data-id` — без этого стрелка вправо «теряла» бы курсор.

## Перетаскивание и групповое выделение

Источник перетаскивания — карточка или строка дерева, цель — папка в дереве, крошка пути или
корень. Что именно едет, хранится в переменной `dragPayload`, а не только в `dataTransfer`:
строковый payload во время `dragover` прочитать нельзя, а подсветить недопустимую цель надо
именно тогда. `canDropInto()` повторяет проверки сервера (внутрь себя, внутрь потомка, не-папка
в корень) — но последнее слово всё равно за сервером, здесь это только подсветка.

Окно «Переместить» осталось: с клавиатуры и с телефона перетащить нечем, а через Funnel сюда
заходят именно с телефона. Оно же обслуживает групповой перенос — `openMoveModal(nodeId, ids)`.

`state.selection` — множество идентификаторов, `selectionAnchor` — точка отсчёта для
`Shift`+клика. Диапазон считается по `visibleCards`, то есть по видимому порядку, а не по
массиву узлов. Выделение сбрасывается при любой смене выборки (папка, поиск, отбор): иначе оно
осталось бы невидимым, а групповое удаление сработало бы по нему.

Групповые операции — цикл запросов на клиенте, пакетной ручки нет. Ошибка на одном элементе
не отменяет остальные: часть могла переехать, и об этом честно сообщается.

## Оффлайн

`public/sw.js` кэширует оболочку и последний ответ `GET /api/nodes` — всё дерево и так лежит
на клиенте одним плоским списком, поэтому чтение без связи стоит почти ничего.

**Стратегия «сначала сеть», и это не случайность.** Обычный для PWA приём «сначала кэш» здесь
опасен: приложение обновляется через `git pull && systemctl restart`, а проверяется
перезагрузкой страницы. С кэшем-первым перезагрузка отдавала бы старый `app.js`, и правка
«не приезжала» бы без видимой причины. Плата — оффлайн включается не мгновенно, а после того
как запрос отвалится.

Не кэшируется никогда: всё под `/api/admin` (доступ к серверу, которому в кэше телефона
не место) и `/api/auth` (кэшированное «вы вошли» пережило бы выход). Сам `sw.js` сервер отдаёт
с `Cache-Control: no-store` — иначе браузер неделю не заметил бы новую версию файла, который
управляет всем остальным.

Выход из аккаунта стирает кэш: в нём лежат личные заметки.

## Разметка текстовых страниц

Текстовая страница хранится как обычный текст, а показывается разобранной: `renderMarkdown()`
в `app.js` понимает заголовки, списки, цитаты, `---`, блоки кода, `**жирный**`, `*курсив*`,
`` `код` `` и `[текст](адрес)`. Библиотеки нет — в проекте нет сборки, и тянуть пакет ради
этого несоразмерно.

**Порядок действий внутри рендерера — защитный, а не стилистический.** Сначала экранируется
весь исходный текст, и только потом по уже экранированной строке расставляются теги. После
экранирования в тексте не остаётся ни одного живого `<`, поэтому HTML, написанный пользователем
руками, показывается как текст и выполниться не может. Менять шаги местами нельзя.

Адреса ссылок проверяются отдельно, по белому списку схем (`http`, `https`, `mailto`):
экранирование кавычек защищает от выхода из атрибута, но не от `javascript:` внутри `href`.
`[текст](javascript:…)` остаётся обычным текстом.

Одиночные переводы строк сохраняются как `<br>` — вопреки каноническому markdown, который их
склеивает. Это заметки, и человек, нажавший Enter, ждёт перевода строки.

Клик по текстовой странице открывает её на чтение (`#text-modal-overlay`), правка — кнопкой
в шапке этого окна. Это единственное место, где пользовательский текст уходит в `innerHTML`.

## Инструкция

`#view-help` — статическая разметка в `index.html`, JS её не собирает: содержимое не зависит ни
от данных, ни от состояния, а иконки в ячейках проставляются общим проходом по `[data-icon]`.
Значит, при изменении интерфейса страницу надо править руками — рассинхрон ничем не ловится.
Новая строка справки требует ещё и ключа в словаре: без `data-t` она останется русской
при украинском интерфейсе (см. [«Языки»](#языки)).

Админские части помечены в разметке: строки таблиц классом `.help-admin-row`, целый блок —
`#help-admin`. Обе группы скрыты в HTML классом `hidden` и открываются только в
`applyAdminVisibility()`, так что обычный пользователь не читает про кнопки, которых у него нет.

## Настройки пользователя

`state.settings` — копия настроек аккаунта, приезжает вместе с `state.user` из
`/api/auth/me`, `/api/auth/login` или `/api/auth/register`; `applyUserSettings()` накладывает её
поверх `DEFAULT_SETTINGS`.

Запись — `saveSetting(key, value)`: оптимистично. Интерфейс перерисовывается сразу, PUT уходит
следом, ответ сервера становится новым состоянием. Если запрос упал — показывается тост, но
откат не делается: цена ошибки — потерянная настройка на следующем входе, и ради неё дёргать
интерфейс обратно хуже, чем оставить как есть.

`DEFAULT_SETTINGS` в `app.js` — зеркало `SETTINGS_SPEC` из `server/user-settings.js`,
синхронизируется руками. Подробности — [data-model.md](data-model.md).

## Языки

Интерфейс двуязычный: украинский и русский, по умолчанию украинский. Язык — обычная настройка
аккаунта (`language` в `SETTINGS_SPEC`), то есть переезжает вместе с ним на любое устройство и не
зависит от браузера. До входа аккаунта нет, поэтому лендинг показывается на языке по умолчанию.

Переводится только интерфейс. Названия папок, текст страниц, имена загруженных документов и
блокнот администраторов — данные пользователя, они остаются такими, какими их ввели.

`TRANSLATIONS` в `app.js` — один словарь вида `ключ: [uk, ru]`. Языки лежат в одной строке
нарочно: добавляя ключ, невозможно молча забыть про один из них, и это видно в одной строке
диффа. Достаёт строку `t(key, vars)`, подстановки — вида `{name}`.

Статическая разметка не дублирует словарь, а помечена атрибутами, которые расставляет
`renderStaticTexts()`:

| Атрибут | Что ставит |
|---|---|
| `data-t` | видимый текст элемента |
| `data-t-html` | то же, но строка содержит строчные теги: `<b>`, `<code>`, бейдж «Админ» |
| `data-t-title` | всплывающую подсказку |
| `data-t-placeholder` | подсказку внутри поля ввода |

Русский текст в самой разметке — не дубль, а то, что видно до загрузки скрипта и что останется,
если ключ однажды исчезнет.

Две ловушки, обе уже стоили отладки:

- **`data-t` меняет только текстовые узлы.** У кнопок первым потомком лежит вставленная иконка,
  у пунктов списка — кружок `.dot`, у подписи загрузки файла — сам `<input>`. Присваивание
  `textContent` стёрло бы их, поэтому `setElementText()` убирает текстовые узлы поимённо.
  Обратная сторона: строку с `<b>` внутри так поставить нельзя — для неё есть `data-t-html`.
- **Неразрывный пробел в словаре — настоящим символом, а не `&nbsp;`.** Строка без тегов
  становится текстовым узлом, где сущность останется видна как есть.

Смена языка ничего не перезагружает: `renderStaticTexts()` проходит по разметке,
`renderDynamicTexts()` перерисовывает дерево, содержимое, открытую панель и вкладки терминала.
Всё, что собрано из словаря один раз при старте, после переключения осталось бы на прежнем
языке — поэтому название типа элемента берётся функцией `typeLabel(type)`, а заголовок вкладки
терминала собирается при отрисовке из номера сессии, а не хранится в ней строкой.

Внутри функций терминала `state.terminal` лежит в переменной `ts`, а не `t`: `t` занято
словарём, и прежнее имя молча перекрывало его внутри этих функций.

## Оформление

Гамма светлая, цветов четыре: синий, зелёный, жёлтый, красный. Все цвета, размеры шрифта,
радиусы, тени и длительности переходов объявлены переменными в блоке `:root` в начале
`style.css`. **Цветовой литерал в правиле ниже — это ошибка:** именно из-за него гамма и разъезжается
по файлу. Нужен новый оттенок — заводите переменную.

Палитра устроена в два слоя. Внизу четыре базовых цвета, у каждого пять значений:

```css
--c-green: #10a35a;                     /* заливка, иконка, крупный элемент */
--c-green-ink: #0a7a43;                 /* мелкий текст на белом: контраст ≥ 4.5:1 */
--c-green-soft: rgba(16, 163, 90, .14); /* подложка под иконку или строку */
--c-green-wash: rgba(16, 163, 90, .10); /* заливка целой карточки */
--c-green-line: rgba(16, 163, 90, .30); /* рамка вокруг неё */
```

`-wash` и `-line` прозрачнее, чем `-soft`, и это не описка: под значком цвет лежит на пятачке
в сорок пикселей, а на карточке — на всей плитке, и та же плотность выжигает глаза. Жёлтый
взят гуще остальных: на белом он светлее их всех и при равной альфе просто пропадает.

Сверху — роли, которые на них ссылаются: `--accent` (синий), `--success` (зелёный),
`--danger` (красный) и четыре `--type-*` под типы элементов. Пятого оттенка в интерфейсе
нет: новая цветная сущность выбирает один из четырёх, а не заводит свой.

Цвет разложен по всему каркасу, а не только по иконкам: полоса `--stripe` под верхней
панелью, активная вкладка (`.tab-btn.active[data-view=…]`), номера шагов в «Инструкции»,
кружки и подсветка фона на лендинге.

Из этого правила три осознанных исключения, поменять их одной переменной нельзя:

- **Лупа в поиске по дереву** — `background-image` с data-URI в `.sidebar-search input`.
  В URI переменную не подставить, цвет прописан константой.
- **Фон терминала** — `#12151b` в `.terminal-pane` и он же в теме xterm в `app.js`.
  Тёмный он не из вкуса: цветовые коды ANSI рассчитаны на тёмный фон. Значения обязаны
  совпадать, иначе xterm покрасит только область под знаками и по краям останется чужая рамка.
- **Иллюстрация лендинга** — SVG в `index.html` со своими константами. Они повторяют
  переменные вручную; меняете палитру — правьте и её.

Тип элемента виден цветом всей карточки: `renderCard()` ставит ей класс `type-<тип>`, а CSS
красит заливку, рамку, полосу по верху и подложку значка в `--type-folder` (синий),
`--type-link` (зелёный), `--type-text` (жёлтый) или `--type-doc` (красный). В режиме списка
заливки нет — полсотни строк, залитых каждая своим цветом, читаются хуже, чем строки
с цветным краем, — и полоса переезжает влево; цвет возвращается под курсором.

Цвет объявляется один раз локальными переменными, а правила ниже их читают:

```css
.item-card.type-link { --tint: var(--type-link); --tint-soft: …; --tint-wash: …; --tint-line: …; }
.item-card           { border-color: var(--tint-line, var(--border)); }
.item-card::before   { background: var(--tint, transparent); }
```

Так один и тот же цвет попадает во все части карточки, а селекторов остаётся по одному
на тип вместо пяти. Второе значение в `var()` — не украшение: без класса `type-*` карточка
обязана остаться белой с серой рамкой. Тот же приём у кнопок создания над содержимым
(`renderToolbar()` ставит им класс `btn-type-<тип>` ровно ради этого). Карточки типов
во вкладке «Инструкция» стоят особняком — там цвет выбирается по атрибуту `data-icon`
в разметке.

Одно следствие заливки стоит держать в голове: `--text-dim` рассчитан на белый фон и на цветной
подложке не дотягивает до 4.5:1. Поэтому описание в карточке (`.item-desc`, самый мелкий шрифт
в интерфейсе) взяло `--text-2`. Добавляете текст поверх `-wash` — проверьте контраст, серый
по умолчанию там не годится.

Дерево в боковой панели различает верхний уровень и вложенный. `renderTreeNode(folder, isRoot)`
ставит корневой строке класс `is-root`, и она получает значок на подложке `--type-folder-soft`
(обёртка `.tree-icon-tile`), основной цвет текста вместо вторичного и счётчик элементов внутри.
Счётчик и кнопка меню лежат в одной ячейке `.tree-tail` и подменяют друг друга по `opacity`:
на 280 пикселях ширины двум элементам справа места нет, а имя папки важнее обоих. На сенсорном
экране подменять нечем — наведения там не бывает, и `@media (hover: none)` раскладывает хвост
в ряд. Вложенные строки остались прежними: на этом контрасте и держится разница уровней.

Отдельно про фокус. Карточки, строки дерева и хлебные крошки — это `div` и `span`
с обработчиком клика: такой элемент не получает фокус табом, то есть с клавиатуры до него
не добраться вообще. Поэтому все три проходят через `makeActivatable()` — она ставит
`tabindex` и роль и вешает Enter с пробелом. Видимую рамку даёт единственное правило
`:focus-visible` в начале `style.css`; поля ввода гасят системный `outline` ради своей рамки,
и это единственное место, где так можно.

## Иконки

**В интерфейсе не должно быть emoji.** Раньше иконками служили `📁 🔗 📝 📄`, и на Linux они
превращались в пустые квадратики: эмодзи-шрифт там обычно не установлен (`fc-list | grep -i emoji`
на этой Pi не находит ничего, и DejaVu Sans, который подставляется по умолчанию, кодовых точек
эмодзи не содержит).

Вместо них — объект `ICONS` в `app.js`: карта `имя → содержимое SVG`, все пути в системе
координат 24×24, обводкой (`stroke`), без заливки. Отсюда следует, что одна и та же иконка
годится в любом размере, а цвет берётся из окружения через `currentColor`.

Два способа вставки:

```js
iconHtml('folder')   // строка <svg …> — для мест, где DOM собирается шаблонной строкой
iconEl('folder')     // готовый элемент — для мест, где DOM собирается createElement
```

Статические кнопки в `index.html` **не** дублируют пути, а помечаются атрибутом:

```html
<button class="icon-btn" id="btn-export-tree" data-icon="download"></button>
```

При загрузке `app.js` проходит по всем `[data-icon]` и вставляет нужный SVG первым потомком.
Так определение иконки остаётся в одном месте.

Размеры задаются в CSS через класс `.icon` (по умолчанию `1.15em`) и точечные переопределения
(`.item-icon .icon`, `.tree-caret .icon` и т. п.). Класс `.icon-spin` крутит иконку — используется
у кнопки «Кратко о ссылке» во время запроса.

Две ловушки:

- **Кнопке с иконкой нельзя присваивать `textContent`** — это сотрёт SVG. Если надо временно
  подменить подпись, работайте с `innerHTML` и восстанавливайте его целиком (так сделано
  в обработчике `#item-fetch-preview`).
- **В `placeholder` элемент не вставить.** Поэтому лупа в поиске по дереву нарисована
  `background-image`-ом с data-URI в `.sidebar-search input`; цвет там прописан константой
  и не следует за темой.

## Экранирование

Там, где DOM собирается шаблонной строкой, любые пользовательские данные обязаны проходить через
`escapeHtml()`. Где можно — используется `textContent` или `document.createTextNode()`, и тогда
экранирование не нужно. Имена иконок в `iconHtml()` — всегда литералы из `ICONS`, пользовательский
ввод туда не попадает.

## Модалки

Все лежат в `index.html` скрытыми (`.hidden`) и показываются переключением класса. Модалка
создания/редактирования одна на все четыре типа узла — нужные поля показываются в
`openItemModal()` по типу. Её размер запоминается в `localStorage` по группе (`ITEM_MODAL_SIZE_PREFIX`):
это настройка окна конкретного браузера, а не аккаунта, поэтому она осознанно осталась локальной.
