# SpriteNote

Личный проводник для хранения информации: папки и подпапки (как в файловом менеджере), ссылки с описанием, текстовые страницы и документы — каждый пользователь видит только своё.

## Стек

- **Backend:** Node.js + Express, MySQL/MariaDB (`mysql2`)
- **Frontend:** чистый HTML/CSS/JS без сборки
- **Auth:** email + пароль (bcrypt), сессии в куках
- Опционально: nginx (TLS-терминация), systemd (автозапуск), Let's Encrypt

## Возможности

- Регистрация/вход, смена пароля, удаление аккаунта (с удалением всех своих данных)
- Первый зарегистрированный пользователь становится администратором
- Дерево: папки/подпапки, ссылки, текстовые страницы, документы — создание/редактирование/удаление/перемещение, поиск по дереву, экспорт/импорт всего дерева в JSON
- Импорт добавляет только то, чего ещё нет: повторная загрузка того же файла не создаёт дублей
- Вкладка «Инструкция» — описание интерфейса и назначение каждой кнопки, админские разделы видны только администраторам
- Два режима отображения содержимого папки — плитка/список; выбор запоминается на аккаунте и переезжает вместе с ним на другое устройство
- «Кратко о ссылке» — по клику сервер сам скачивает страницу по URL и просит `claude` CLI (см. `server/link-summary.js`) сгенерировать краткое название и описание на русском
- Панель управления для администраторов: список пользователей, назначение админов, размер данных на пользователя, файловый менеджер сервера (просмотр/загрузка/скачивание), общий блокнот, веб-терминал (полноценный shell через WebSocket + `node-pty`)

## Установка

```bash
npm install
cp .env.example .env      # заполнить DB_PASSWORD и, при необходимости, DUCKDNS_*
# отредактировать scripts/init-db.sql — заменить CHANGE_ME на тот же пароль, что в .env
sudo mariadb -u root < scripts/init-db.sql
npm start
```

Приложение слушает `HOST:PORT` из `.env` (по умолчанию `127.0.0.1:3000`). Для продакшена — nginx как reverse proxy с TLS, `scripts/spritenote.service` как пример systemd-юнита.

## Безопасность

- Каждый мутирующий эндпоинт защищён `requireAuth` (+ `requireAdmin` для админ-функций), все данные фильтруются по `user_id`
- Rate limiting на `/api/auth/login`, `/api/auth/register` и `/api/nodes/link-summary`
- «Кратко о ссылке» резолвит и валидирует IP перед подключением (блокирует приватные/loopback/link-local адреса, включая метаданные облака), redirect-цепочки проверяются на каждом хопе
- Панель управления (файловый менеджер, терминал) — только для администраторов; веб-терминал даёт полный доступ к серверу от имени пользователя, под которым запущено приложение — включайте эту функциональность осознанно

## Структура

```
server/
├── index.js          # express app, middleware, rate limiting
├── db.js             # mysql2 pool
├── schema.js         # ensureSchema() — доколонки для уже развёрнутых БД
├── auth.js           # сессии, middleware requireAuth/requireAdmin
├── user-settings.js   # спецификация пользовательских настроек
├── terminal.js        # веб-терминал (WebSocket + node-pty), admin-only
├── link-summary.js    # «Кратко о ссылке»
└── routes/
    ├── auth.js         # регистрация/вход/пароль/удаление аккаунта
    ├── nodes.js         # CRUD дерева, move, export/import, link-summary
    └── admin.js         # пользователи, файловый менеджер, блокнот
public/
├── index.html / css/style.css / js/app.js   # SPA без фреймворка
└── vendor/xterm/      # xterm.js, вендорено локально
scripts/
├── init-db.sql                 # схема БД
├── spritenote.service           # пример systemd-юнита приложения
├── duckdns-update.sh/.service/.timer
└── nginx-spritenote.conf        # пример конфига nginx (TLS + security headers + WS)
```
