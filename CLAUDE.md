# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Основной документ для разработчика — [AGENTS.md](AGENTS.md) (архитектура, принципы, грабли),
детали по модулям — [docs/](docs/). Здесь только выжимка и то, что нужно именно при работе агента.

## Субагенты

В `.claude/agents/` лежат четыре субагента под этот проект. Запускать их не обязательно —
для обычной правки в один-два файла быстрее сделать самому. Смысл в них появляется, когда
задача крупная или её надо отдать целиком:

- `spritenote-backend` — правки в `server/` и `scripts/init-db.sql`;
- `spritenote-frontend` — `public/js/app.js`, `index.html`, стили;
- `spritenote-security` — аудит изоляции по `user_id`, прав, SSRF и админских поверхностей;
  только читает и докладывает;
- `spritenote-docs` — AGENTS/README/docs, CHANGELOG, TODO, журнал сессий, вкладка «Инструкция».

Инварианты продублированы внутри каждого файла: субагент стартует с чистым контекстом и
этот CLAUDE.md не видит. Меняете правило здесь — проверьте, не устарела ли копия там.

## Команды

```bash
npm start                              # node server/index.js, слушает HOST:PORT из .env (по умолчанию 127.0.0.1:3000)
sudo systemctl restart spritenote      # на боевой Pi приложение крутится systemd-юнитом
journalctl -u spritenote -f            # логи
curl -s localhost:3000/api/health      # проверка живости
```

Автотестов, линтера и сборки в проекте **нет** — и вводить их без явной просьбы не нужно.
Проверка серверных изменений — поднять экземпляр на отдельной БД и порту (рецепт с созданием
`spritenote_test` и `DB_NAME=... PORT=3099 node server/index.js` — в конце AGENTS.md).
Фронтенд проверяется перезагрузкой страницы: сборки нет, файл из `public/` уходит в браузер как есть.

## Архитектура в двух абзацах

Express-сервер (`server/index.js`) отдаёт JSON API и статику из `public/`. Данные — MariaDB через
`mysql2/promise`, без ORM. Три роутера: `/api/auth`, `/api/nodes`, `/api/admin`; защита ставится
на роутер целиком (`router.use(requireAuth)` / `requireAuth, requireAdmin`), а не на отдельные ручки.
Веб-терминал висит не на express, а на WebSocket-апгрейде (`attachTerminal(server)`), поэтому
`terminal.js` проверяет путь, куку и права админа сам.

Всё содержимое — одна таблица `nodes` (`folder` / `link` / `text` / `doc`) с `parent_id`.
`GET /api/nodes` отдаёт **весь плоский список** дерева пользователя; иерархия, хлебные крошки и
поиск считаются в браузере в `public/js/app.js` (один IIFE, объект `state`, полная перерисовка).
Это сознательный размен: при росте базы до десятков тысяч узлов переделывать надо будет именно это.

## Инварианты, которые легко нарушить

- **`WHERE user_id = ?` в каждом запросе к `nodes`.** Принадлежность проверяется через
  `getOwnNode()`, а не доверием к id из тела запроса.
- **`AND deleted_at IS NULL` — там же.** Удаление мягкое: узел с датой лежит в корзине месяц,
  а потом его убирает `server/trash.js`. Запрос без этого фильтра покажет корзину как живое
  дерево. Ручки корзины — единственные, кто зовёт `getOwnNode(..., { includeDeleted: true })`.
- **Схема БД живёт в двух файлах:** `scripts/init-db.sql` (свежая установка) и `server/schema.js`
  (`ensureSchema()` доливает колонки в уже развёрнутую БД). Новая колонка — правьте оба.
- **Порядок парсеров в `server/index.js`:** `express.json({limit:'1gb'})` для `/api/nodes/import`
  обязан регистрироваться до общего `5mb`, иначе импорт с вложенными документами падает по лимиту.
- **Ошибки — коды, не тексты.** Сервер возвращает `{ error: 'some_code' }`; русский текст —
  в `ERROR_MESSAGES` в `public/js/app.js`. Новый код без перевода = «Произошла ошибка» у пользователя.
- **Настройки пользователя** описываются одним `SETTINGS_SPEC` в `server/user-settings.js`;
  на клиенте есть ручное зеркало `DEFAULT_SETTINGS` в `app.js` — синхронизировать самому.
- **Вкладка «Инструкция»** (`#view-help`) — статическая разметка в `index.html`. Меняете интерфейс —
  правьте её руками, рассинхрон ничем не ловится.
- **Интерфейс двуязычный** (украинский по умолчанию, русский вторым). Любой новый видимый текст —
  строка `ключ: [uk, ru]` в `TRANSLATIONS` в `app.js` плюс `data-t` (или `data-t-html`, если внутри
  есть `<b>`, `<code>`, бейдж) в разметке. Без ключа текст останется русским при украинском
  интерфейсе. Неразрывный пробел в словаре — символом, не `&nbsp;`. Данные пользователя
  (названия папок, текст страниц, документы) не переводятся никогда. Подробности —
  [docs/frontend.md](docs/frontend.md).
- **Цвета и размеры — только переменными из `:root`** в начале `style.css`. Из-за литерала
  в правиле ниже гамма разъезжается. Цветов в палитре четыре — синий, зелёный, жёлтый, красный
  (`--c-*` с оттенками `-ink`, `-soft`, `-wash`, `-line` — от мелкого текста до заливки целой
  карточки); новая цветная сущность выбирает один из них, а не заводит пятый оттенок. Три исключения (лупа в поиске, фон терминала, иллюстрация лендинга)
  перечислены в [docs/frontend.md](docs/frontend.md); фон терминала продублирован в `app.js`
  и обязан совпадать.
- **Защиты в `server/link-summary.js` не упрощать:** проверка IP, пиннинг соединения на уже
  проверенный адрес, ручной разбор редиректов. Это единственное место, где сервер ходит по
  пользовательскому URL, — и `server/link-check.js` пользуется тем же `safeFetch`, а не своим.
- **Пользовательский текст в `innerHTML` — только через `renderMarkdown()`** в `app.js`, и только
  в его порядке: сначала экранируется весь исходник, потом расставляются теги. Схемы ссылок —
  по белому списку (`http`, `https`, `mailto`), иначе `[текст](javascript:…)` станет рабочим.
- **Service worker — «сначала сеть».** `public/sw.js` кэширует оболочку и `GET /api/nodes`
  только как запасной путь. Кэш-первым перезагрузка страницы отдавала бы старый `app.js`,
  и правка «не приезжала» бы после рестарта. `/api/admin` и `/api/auth` не кэшируются никогда,
  выход из аккаунта стирает кэш.
- **Импорт только добавляет.** Тождество узла — родитель + тип + имя (без учёта регистра);
  повторный импорт того же файла обязан быть пустой операцией.

## Конвенции

- Интерфейс, документация, коммиты, ответы пользователю — по-русски. Идентификаторы и комментарии
  в коде — по-английски. Комментарий объясняет «почему», а не «что».
- **Никаких emoji в интерфейсе** — иконки берутся из `ICONS` в `app.js` (inline-SVG). На целевой
  Linux-машине эмодзи-шрифта нет, они рисуются квадратиками.
- Каждая рабочая сессия — файл `docs/sessions/YYYY-MM-DD.md` (каталог в git не уходит: там детали
  конкретного сервера). Заметные изменения — строкой в [CHANGELOG.md](CHANGELOG.md),
  незакрытые хвосты — в [TODO.md](TODO.md).
- `data/` (загруженные документы) и `.env` не коммитятся.

## Про доступ

Права админа здесь ≈ SSH на сервер: файловый менеджер видит всю ФС, веб-терминал — настоящий shell
без песочницы, `GET /api/admin/project-zip` отдаёт каталог проекта без `.env`, но вместе с
`data/uploads` — то есть с документами всех пользователей. Учитывайте это,
предлагая что-либо вынести наружу. Каталог проекта нельзя переименовывать или переносить — на него
завязаны systemd-юнит и хуки продления сертификата в `/etc/letsencrypt/renewal/`.
